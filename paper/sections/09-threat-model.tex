\subsubsection{Threat matrix}
\label{sec:threats}

Explicit semantic structure may improve observability and constrain some behaviors, but it also creates attack surfaces. An attacker might poison a source, spoof authority, manipulate purpose relevance, hide a moral patient, steer routing, or bypass the verifier. Security is therefore part of the architecture rather than an afterthought.

Prompt injection and jailbreaks test whether context can overwhelm learned or structural constraints \citep{zou2023universal,wei2023jailbroken}. Goal misgeneralization, reward hacking, and fine-tuning regressions test whether a system pursues an unintended objective while retaining competence \citep{langosco2022goalmisgeneralization,shah2022goalmisgeneralization,gao2023overoptimization,qi2023finetuning}. Explicit structure adds distinct compromise paths: a model may reason correctly from a poisoned graph, a malicious compiler may produce a plausible module, or a purpose resolver may suppress relevant context.

The security objective is not “no attacks.” It is measurable reduction in attack success, faster detection, bounded blast radius, preserved provenance, and safe failure when the architecture is uncertain or contradictory. Every future implementation should separately test source integrity, representation conformance, runtime context integrity, router behavior, and the exact action-verifier path.
